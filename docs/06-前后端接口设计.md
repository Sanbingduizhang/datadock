# DataDock 前后端接口设计

> 文档版本：V1.0
> 文档状态：接口设计
> 适用版本：V1.0（MySQL）
> 所属项目：DataDock

## 1. 文档说明

### 1.1 编写目的

本文档用于定义 DataDock 前端与 Rust 后端之间的通信规范。

DataDock 使用 Tauri 作为桌面应用框架，前端负责 UI 和交互，Rust 后端负责数据库连接、本地数据存储、SQL 执行和文件操作。

双方通过 Tauri IPC 进行通信。

本文档主要解决：

1. 前端如何调用 Rust 后端？
2. 后端提供哪些 Command？
3. 每个 Command 接收什么参数？
4. 每个 Command 返回什么数据？
5. 后端如何通知前端任务执行状态？
6. 如何统一错误码和错误信息？
7. 如何避免前后端类型不一致？

### 1.2 设计原则

- 所有接口统一使用 snake_case 命名。
- TypeScript 接口统一使用 camelCase 字段。
- Rust 内部可以使用 snake_case，通过 Serde 统一序列化规则。
- 请求参数必须有明确类型。
- 返回值必须有明确类型。
- 所有错误必须有统一错误码。
- 长时间运行的任务不能阻塞 Command 调用。
- 任务进度和状态通过 Tauri Event 通知前端。
- 前端不能直接操作 SQLite 或远程 MySQL。
- 敏感信息不能通过普通接口长期传递或持久化。
- 不允许前后端各自定义一套相互冲突的数据结构。

### 1.3 接口分类

| 接口类型         | 用途                                |
| ---------------- | ----------------------------------- |
| Command          | 前端主动调用后端                    |
| Event            | 后端主动通知前端                    |
| Internal Service | Rust 后端内部模块调用，不暴露给前端 |
| Repository       | 后端数据持久化接口，不暴露给前端    |

## 2. 通信架构

### 2.1 整体通信流程

```
┌────────────────────────────────────┐
│              Vue Frontend          │
│                                    │
│  Components / Views / Pinia        │
│                │                   │
│                ▼                   │
│          API Service Layer         │
└────────────────┬───────────────────┘
                 │
                 │ Tauri IPC
                 ▼
┌────────────────────────────────────┐
│             Rust Backend           │
│                                    │
│          Tauri Commands            │
│                │                   │
│                ▼                   │
│           Service Layer            │
│                │                   │
│                ▼                   │
│          Repository / Adapter      │
│                                    │
└────────────────┬───────────────────┘
                 │
          ┌──────┴──────┐
          ▼             ▼
       SQLite        Remote MySQL
```

### 2.2 前端职责

前端负责：

- 用户输入。
- 参数初步校验。
- 调用 Command。
- 展示返回结果。
- 订阅后端 Event。
- 管理页面状态。
- 展示错误信息。
- 维护工作区状态。

前端不负责：

- 数据库连接。
- 数据库密码持久化。
- SQL 执行。
- SQLite 操作。
- 数据库结构查询。
- 文件底层写入。
- 数据库连接池管理。

### 2.3 后端职责

Rust 后端负责：

- 参数二次校验。
- 业务逻辑。
- 数据库连接管理。
- SQL 执行。
- 查询结果转换。
- 本地 SQLite 存储。
- 系统凭据管理。
- 文件导出。
- 后台任务管理。
- 错误处理。

## 3. 命名规范

### 3.1 Command 命名

使用 snake_case。

例如：

```
create_connection
update_connection
delete_connection
test_connection
connect_database
disconnect_database
execute_sql
cancel_task
query_table_data
```

### 3.2 TypeScript 方法命名

使用 camelCase。

```
createConnection()
updateConnection()
deleteConnection()
testConnection()
connectDatabase()
disconnectDatabase()
executeSql()
cancelTask()
queryTableData()
```

### 3.3 数据字段命名

前端统一使用 camelCase：

```
interface ConnectionInfo {
  connectionId: string;
  connectionName: string;
  currentDatabase?: string;
}
```

Rust 可以使用 snake_case：

```
struct ConnectionInfo {
    connection_id: String,
    connection_name: String,
    current_database: Option<String>,
}
```

通过 Serde 的序列化规则统一转换。

建议在项目中统一使用 camelCase 序列化策略，避免部分结构体单独转换。

## 4. 公共类型定义

以下 TypeScript 类型建议统一放在：

```
src/types/api.ts
```

### 4.1 基础类型

```
export type DataSourceType = 'mysql';

export type ConnectionStatus =
  | 'disconnected'
  | 'connecting'
  | 'connected'
  | 'error';

export type QueryTaskStatus =
  | 'pending'
  | 'running'
  | 'success'
  | 'failed'
  | 'cancelled';

export type TaskType =
  | 'query'
  | 'export';
```

### 4.2 统一错误结构

```
export interface AppError {
  code: string;
  message: string;
  details?: Record<string, unknown>;
}
```

错误说明：

- code：程序可识别的错误码。
- message：面向用户的错误信息。
- details：可选的补充信息。

不能在 details 中包含数据库密码、访问令牌等敏感信息。

### 4.3 分页结构

```
export interface PageRequest {
  page: number;
  pageSize: number;
}

export interface PageResult<T> {
  items: T[];
  page: number;
  pageSize: number;
  total?: number;
  hasMore: boolean;
}
```

### 4.4 数据库值类型

```
export type DatabaseValue =
  | { type: 'null'; value: null }
  | { type: 'boolean'; value: boolean }
  | { type: 'integer'; value: string }
  | { type: 'float'; value: number }
  | { type: 'decimal'; value: string }
  | { type: 'string'; value: string }
  | { type: 'date'; value: string }
  | { type: 'datetime'; value: string }
  | { type: 'time'; value: string }
  | { type: 'json'; value: unknown }
  | { type: 'binary'; value: string };
```

约束：

- integer 使用字符串承载，避免大整数精度丢失。
- decimal 使用字符串承载。
- null 使用独立类型。
- binary 需要明确编码方式，建议使用 Base64。
- 日期和时间使用明确的字符串格式。
- 后端必须对无法识别的类型进行安全处理。

### 4.5 数据库列信息

```
export interface QueryColumn {
  name: string;
  typeName?: string;
  nullable?: boolean;
}
```

### 4.6 查询结果

```
export interface QueryResultSet {
  columns: QueryColumn[];
  rows: DatabaseValue[][];
  rowCount: number;
  truncated: boolean;
}

export interface QueryExecutionResult {
  taskId: string;
  status: QueryTaskStatus;
  resultSets: QueryResultSet[];

  affectedRows?: number;
  lastInsertId?: string;

  executionTimeMs: number;
  error?: AppError;
}
```

说明：

这里的 `rows` 是二维数组，每个内层数组对应一行数据。

`rowCount` 表示当前返回的记录数量，不应与数据库总记录数混淆。

## 5. 连接管理接口

接口模块：

```
src/api/connection.ts
```

### 5.1 创建连接

Command：

```
create_connection
```

请求：

```
export interface CreateConnectionRequest {
  name: string;
  sourceType: 'mysql';

  host: string;
  port: number;
  username: string;
  password: string;

  defaultDatabase?: string;
  charset?: string;
  connectTimeoutMs?: number;
}
```

返回：

```
export interface CreateConnectionResponse {
  connectionId: string;
}
```

说明：

- password 仅用于创建连接时提交。
- 后端负责将密码保存到系统凭据服务。
- SQLite 只保存 credentialKey。
- 创建成功后，前端不再保留密码。
- 如果保存凭据或数据库配置失败，需要进行一致性处理。

### 5.2 修改连接

Command：

```
update_connection
```

请求：

```
export interface UpdateConnectionRequest {
  connectionId: string;

  name: string;
  host: string;
  port: number;
  username: string;

  defaultDatabase?: string;
  charset?: string;
  connectTimeoutMs?: number;

  newPassword?: string;
}
```

返回：

```
export interface UpdateConnectionResponse {
  success: boolean;
}
```

说明：

- newPassword 不传表示保留原密码。
- 修改连接参数时，需要判断是否影响当前运行时连接。
- 如果连接正在使用，应提示用户重新连接，或由后端按照明确策略重建连接。
- 不允许无提示地破坏正在执行的任务。

### 5.3 删除连接

Command：

```
delete_connection
```

请求：

```
export interface DeleteConnectionRequest {
  connectionId: string;
}
```

返回：

```
export interface DeleteConnectionResponse {
  success: boolean;
}
```

处理规则：

1. 检查连接是否存在。
2. 处理运行时连接。
3. 处理关联任务。
4. 删除 SQLite 连接配置。
5. 删除对应系统凭据。
6. 保留查询历史和 SQL 收藏。

如果连接正在执行任务，应按照连接管理模块定义的规则处理，不能直接删除运行时资源。

## 7. SQL 执行接口

接口模块：

```
src/api/query.ts
```

### 7.1 执行 SQL

Command：

```
execute_sql
```

请求：

```
export interface ExecuteSqlRequest {
  connectionId: string;
  databaseName?: string;

  sql: string;

  executionMode:
    | 'current'
    | 'selected'
    | 'all';

  options?: {
    maxRows?: number;
    timeoutMs?: number;
  };
}
```

返回：

```
export interface ExecuteSqlResponse {
  taskId: string;
  status: 'pending' | 'running';
}
```

设计说明：

SQL 执行可能需要较长时间，因此 Command 只负责提交任务并返回 taskId。

不建议等待 SQL 完全执行结束后才返回 Command。

后端通过 TaskManager 管理任务，执行完成后通过 Event 通知前端。

Command：

```

```


```
export interface CancelTaskResponse {
  taskId: string;
```

说明：

- 取消请求不等于数据库服务端已经停止执行。
- 后端需要根据驱动能力判断取消方式。
- 如果驱动无法取消，应返回明确结果。
- 如果取消仍在处理中，可以通过 Event 通知最终状态。

## 8. 查询结果接口

### 8.1 获取查询结果

Command：

```
get_query_result
```

请求：

```
export interface GetQueryResultRequest {
  taskId: string;
}
```

返回：

```
export interface GetQueryResultResponse {
  taskId: string;

  status: QueryTaskStatus;

  resultSets: QueryResultSet[];

  affectedRows?: number;
  lastInsertId?: string;

  executionTimeMs?: number;

  error?: AppError;
}
```

说明：

- 查询结果需要关联 taskId。
- 结果只在任务完成后视为最终结果。
- 失败任务可以返回已经产生的部分结果，但是否保留需要结合驱动能力确定。
- 结果集较大时，应考虑分批传输或独立结果读取接口，避免一次性通过 IPC 传输过多数据。

### 8.2 清理查询结果

```
}
```

返回：

```

  success: boolean;
}
```

用于用户关闭结果标签或后端需要释放大结果集时清理相关资源。

注意：清理结果不能删除已经保存的查询历史。

### 16.9 事件订阅规则

前端必须：

1. 在需要监听的页面或 Store 初始化时注册事件。
2. 保存事件监听器的取消函数。
3. 页面销毁或不再需要监听时取消订阅。
4. 根据 taskId 更新对应任务。
5. 忽略无法识别的任务事件。
6. 不允许重复注册相同业务监听器而不清理旧监听器。

事件只能作为状态通知机制。

不能假设前端在休眠、刷新或重新打开后一定收到了之前的事件。

重新进入任务页面时，应通过 `list_tasks` 或 `get_task` 查询当前状态。

```
import { invoke } from '@tauri-apps/api/core';
```

### 17.3 连接 API 示例

```
import { invokeCommand } from './index';

import type {
  CreateConnectionRequest,
  CreateConnectionResponse,
  ConnectionInfo,
  TestConnectionRequest,
  TestConnectionResponse,
} from '@/types/connection';

export function createConnection(
  params: CreateConnectionRequest
) {
  return invokeCommand<CreateConnectionResponse>(
    'create_connection',
    { request: params }
  );
}

export function listConnections() {
  return invokeCommand<ConnectionInfo[]>(
    'list_connections'
  );
}

export function testConnection(
  params: TestConnectionRequest
) {
  return invokeCommand<TestConnectionResponse>(
    'test_connection',
    { request: params }
  );
}
```

说明：

如果具体 Tauri 版本或 Command 注册方式需要调整，应统一修改封装规则，而不是每个接口采用不同参数形式。

## 18. Rust Command 实现规范

### 18.1 Command 层职责

Command 只负责：

1. 接收参数。
2. 基础参数校验。
3. 调用 Service。
4. 返回结果。

Command 不负责：

- 直接拼接复杂 SQL。
- 直接操作 SQLite。
- 管理连接池细节。
- 直接实现查询历史业务。
- 直接执行文件导出业务。

### 18.2 示例

```
#[tauri::command]
async fn create_connection(
    request: CreateConnectionRequest,
    state: tauri::State<'_, AppState>,
) -> Result<CreateConnectionResponse, AppError> {
    state
        .connection_service
        .create_connection(request)
        .await
}
```

以上为结构示意。

实际代码需要根据 AppState 的所有权、Arc 共享方式和 Tauri 状态管理规则实现。

### 18.3 Command 注册

建议集中注册：

```
tauri::Builder::default()
    .manage(app_state)
    .invoke_handler(tauri::generate_handler![
        create_connection,
        update_connection,
        delete_connection,
        list_connections,
        test_connection,
        connect_database,
        disconnect_database,
        get_connection_status,
        execute_sql,
        get_task,
        cancel_task,
        query_table_data,
        get_table_schema
    ]);
```

后续增加接口时，需要同步维护注册列表。

## 19. 参数校验规范

所有接口必须在后端执行参数校验。

### 19.1 连接参数

| 字段     | 校验                 |
| -------- | -------------------- |
| name     | 不允许为空           |
| host     | 不允许为空           |
| port     | 必须在有效端口范围内 |
| username | 根据连接方式校验     |
| password | 创建或修改凭据时校验 |
| charset  | 必须是支持的字符集   |

### 19.2 SQL 参数

| 字段          | 校验             |
| ------------- | ---------------- |
| connectionId  | 必须存在         |
| databaseName  | 必须合法且可访问 |
| sql           | 不允许为空       |
| executionMode | 必须是允许值     |
| maxRows       | 必须在合理范围   |
| timeoutMs     | 必须在合理范围   |

### 19.3 分页参数

| 字段     | 校验           |
| -------- | -------------- |
| page     | 大于等于 1     |
| pageSize | 大于 0         |
| pageSize | 不超过后端限制 |

### 19.4 表操作参数

必须校验：

- connectionId。
- databaseName。
- tableName。
- 字段是否真实存在。
- 操作类型是否允许。
- 主键或唯一键定位条件。
- 字段值类型。

前端校验不能替代后端校验。

## 20. 错误码规范

建议统一维护错误码定义。

| 错误码                       | 含义               |
| ---------------------------- | ------------------ |
| CONNECTION_NOT_FOUND         | 连接不存在         |
| CONNECTION_NOT_READY         | 连接未就绪         |
| CONNECTION_FAILED            | 连接失败           |
| CONNECTION_ALREADY_CONNECTED | 连接已经建立       |
| CONNECTION_BUSY              | 连接正在执行任务   |
| CREDENTIAL_NOT_FOUND         | 凭据不存在         |
| CREDENTIAL_ACCESS_FAILED     | 凭据读取失败       |
| DATABASE_NOT_FOUND           | 数据库不存在       |
| TABLE_NOT_FOUND              | 表不存在           |
| SQL_EMPTY                    | SQL 内容为空       |
| SQL_EXECUTION_FAILED         | SQL 执行失败       |
| QUERY_CANCELLED              | 查询取消           |
| QUERY_TIMEOUT                | 查询超时           |
| TASK_NOT_FOUND               | 任务不存在         |
| TASK_NOT_CANCELLABLE         | 任务不支持取消     |
| INVALID_ARGUMENT             | 参数无效           |
| INVALID_FILTER               | 筛选条件无效       |
| INVALID_SORT                 | 排序条件无效       |
| UNSAFE_ROW_OPERATION         | 无法安全定位数据行 |
| PERMISSION_DENIED            | 权限不足           |
| STORAGE_ERROR                | 本地存储错误       |
| EXPORT_FAILED                | 导出失败           |
| FILE_ACCESS_DENIED           | 文件访问被拒绝     |
| INTERNAL_ERROR               | 内部错误           |

### 20.1 错误处理原则

- 程序通过 code 判断错误类型。
- 用户通过 message 理解错误原因。
- details 只提供必要的诊断信息。
- 不将完整数据库连接字符串写入错误信息。
- 不将密码写入日志。
- 不向用户展示 Rust 内部堆栈作为普通错误提示。

## 21. 接口实现与类型同步

### 21.1 类型唯一来源

前后端类型必须保持一致。

建议：

- TypeScript 类型集中放在 `src/types`。
- Rust 类型集中放在 `src-tauri/src/models`。
- 使用统一命名规则。
- 对关键请求和响应编写序列化测试。

后续可以考虑通过 JSON Schema、Specta 或其他工具生成前端类型。

是否采用自动生成，需要结合最终 Tauri 版本和依赖生态验证后决定。

不能同时手工维护多份互相矛盾的类型定义。

### 21.2 类型变更规则

修改接口时：

1. 修改 Rust 数据模型。
2. 修改 TypeScript 类型。
3. 修改 Command。
4. 修改前端 API 封装。
5. 修改对应调用页面。
6. 修改接口测试。
7. 检查其他依赖模块。

禁止只修改前端类型，不修改后端实际返回结构。

### 21.3 接口版本

V1.0 暂时不需要为每个 Command 添加版本号。

但需要为工作区等可能长期保存的结构预留 version 字段。

如果未来接口发生不兼容变化，应当明确迁移策略。

## 23. AI 开发约束

AI 编码时必须遵守：

1. 所有 Command 必须在本文件中定义或经过明确补充。
2. 不允许前端自行猜测后端参数。
3. 不允许 Rust 后端返回未定义的字段。
4. 不允许前后端使用不同的状态枚举。
5. 不允许将错误信息作为唯一错误判断依据。
6. 不允许将长时间运行的 SQL 放在同步阻塞流程中。
7. 不允许使用 Event 替代最终任务状态查询。
8. 不允许忽略 Event 监听器清理。
9. 不允许在接口中返回数据库密码。
10. 不允许将任意 SQL 片段作为筛选参数传入。
11. 不允许前端传入行号作为数据修改定位条件。
12. 不允许一次性传输不受控制的大型结果集。
13. 不允许绕过 Service 直接操作 Repository。
14. 所有接口必须具备参数校验和错误处理。
15. 接口变更必须同步修改前后端类型和测试。
