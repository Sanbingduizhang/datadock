# DataDock 技术决策记录

> 记录影响架构的技术验证与选型结论。每条决策包含：背景、验证方式、结论、影响。

## TDR-001 MySQL 驱动选型与能力边界

- **日期**：2026-11-18
- **状态**：已验证（MySQL 8.4.13，macOS arm64）
- **驱动**：`sqlx 0.8.6`（features：`runtime-tokio`、`mysql`、`json`、`chrono`、`bigdecimal`）

### 背景

`docs/03` 要求先验证驱动是否满足数据库客户端场景：任意 SQL、多语句、多结果集、字段类型、流式读取、事务、取消、断线恢复。
验证脚本：`src-tauri/tests/mysql_poc.rs`（`#[ignore]`，需真实环境）。

### 验证结果

| 能力 | 结果 | 说明 |
| --- | --- | --- |
| 连接与认证 | 通过 | MySQL 8.4 `caching_sha2_password` 在非 TLS 下可正常认证（驱动自动处理 RSA 公钥） |
| 任意 SQL | 通过 | `sqlx::query`（预处理）与 `sqlx::raw_sql` 均可用 |
| 多语句（一次提交） | **不支持** | 预处理路径直接返回 1064 语法错误；`raw_sql` 只返回单个 `QueryResult`，拿不到逐条结果 |
| 多结果集 | **驱动层不支持** | 同上 |
| 字段类型 | 通过 | 见下表 |
| BIGINT UNSIGNED | 通过 | `u64` 读取 `18446744073709551615` 无损 |
| DECIMAL 精度 | 通过（需 `bigdecimal`） | `BigDecimal` 读到 `12345678901234567890.1234567890`；**`f64` 读取被驱动拒绝**（类型不匹配） |
| JSON / BLOB / DATETIME | 通过 | `serde_json::Value` / `Vec<u8>` / `NaiveDateTime` |
| TINYINT(1) | 通过 | 驱动类型报告为 `BOOLEAN`，按 `i8`/`bool` 读取 |
| 流式读取 | 通过 | `fetch()` 逐行读取 300 行耗时 ~1.5ms |
| 事务 | 通过 | `begin/commit/rollback` 行为正确 |
| 服务端取消 | 通过（需外部连接） | 另开连接执行 `KILL QUERY <id>`，`SELECT SLEEP(10)` 在 ~413ms 返回 |
| information_schema | 需适配 | MySQL 8.4 中 `TABLE_TYPE`、`COLUMN_NAME` 等列返回 **BINARY**，必须 `CAST(... AS CHAR)`；`SEQ_IN_INDEX` 为 `INT UNSIGNED`，需按 `u64` 读取 |

### 结论

1. 继续使用 **sqlx** 作为 MySQL 驱动，不更换。
2. **多语句 / 多结果集在应用层实现**：客户端切分 SQL → 逐条执行 → 汇总为 `Vec<ResultSet>`。切分必须使用状态机（引号、反引号、注释、`DELIMITER`），禁止简单按分号 `split`。
3. **查询取消采用 `KILL QUERY`**：每个连接记录 `CONNECTION_ID()`，取消时通过独立控制连接执行 `KILL QUERY`。
4. **取消后的状态由应用层判定**：被 KILL 的语句可能正常返回（如 `SLEEP()` 返回 1 而非报错），不能依赖驱动报错判断「已取消」。
5. **DECIMAL 一律走 `BigDecimal` → 字符串**传给前端，禁止经 `f64`，避免精度损失。
6. **元数据查询统一 `CAST(... AS CHAR)`**，并按无符号类型读取计数列。

### 影响

- `docs/11` 中「驱动能力待确认」的条目可以关闭。
- 阶段 E 需要一个 SQL 切分模块（独立于驱动），并有单元测试覆盖注释/引号/存储过程场景。
- 连接管理器需要为每个连接保存 `CONNECTION_ID()` 与一个控制连接（或复用池内另一连接）用于取消。

## TDR-002 查询执行：按库连接池与执行器借用限制

- **日期**：2026-11-18
- **状态**：已验证（MySQL 8.4.13 + rustc 1.100）

### 背景

阶段 E 首次实现 `execute_sql` 时，三种写法都无法通过编译：

1. `sqlx::query(sql).fetch(&mut *pool_conn)`：报 `Executor` 未针对 `&mut PoolConnection` 实现；
2. 改为 `&mut MySqlConnection` 局部变量：报 `implementation of Executor is not general enough`（rustc 1.100 收紧的 HRTB 检查）；
3. 把执行放进 `tokio::spawn`：同样的 HRTB + Send 错误。

同时需要解决「不同数据库上下文隔离」：`USE db` 只作用于当前连接，连接池中其他连接不受影响。

### 结论

1. **按数据库缓存连接池**：`ManagedConnection::pool_for(database)` 在首次访问某库时用同一份连接参数（含密码，仅内存）建立独立的小池（max 2，空闲 120s 回收），断开连接时统一关闭。
   - 好处：数据库上下文天然隔离，无需 `USE`，也彻底避开 `&mut Connection` 的执行器借用问题（使用 `&MySqlPool` 作为 Executor）。
2. **结果行数用会话变量限制**：执行前 `SET SESSION sql_select_limit = max_rows + 1`，再 `fetch_all`，最后截断并标记 `truncated`。
   - 满足「不改写用户 SQL」的要求，同时保证内存有界（最多 max_rows+1 行）。
3. 默认 `max_rows = 1000`，上限 10000，可由请求覆盖。

### 影响

- 每个连接可能同时存在多个小池（主库 + 访问过的库），断开时全部关闭；退出流程已覆盖。
- 空结果集暂时没有列头（未使用 `describe`，因为它同样触发上述借用问题）；后续可用独立 `MySqlConnection` 或驱动层描述接口补齐。
- 多语句/多结果集、服务端取消（`KILL QUERY`）仍待阶段 E 后续迭代。

## TDR-003 多语句执行、查询取消与历史记录

- **日期**：2026-11-18
- **状态**：已验证（MySQL 8.4.13，集成测试覆盖多语句、失败中断与取消）

### 背景

`docs/06` 7.1 规定 `execute_sql` 只提交任务并返回 `taskId`，通过 `get_task` 轮询与事件通知获取结果。实际实现选择**同步返回完整结果 + 客户端 taskId**：

1. 桌面单机场景下查询结果需要立即渲染，事件 + 轮询会额外引入状态机与事件订阅两套代码；
2. 取消能力并不依赖异步任务模型：`cancel_task` 是独立 Command，可以在 `execute_sql` 的 Promise 未完成时并发调用；
3. 任务表、进度、事件通道属于「长任务/批量导入」需求，等真需要时再引入，避免现在过度设计。

### 结论

1. **执行模型**：`execute_sql` 同步返回全部结果；请求携带前端生成的 `taskId`，`cancel_task(taskId)` 并发取消。响应含 `taskId`、`results[]`、`error`、`cancelled`、`historyId`。
2. **语句会话**：每条 SQL 请求独立创建一个 `max_connections = 1` 的连接池（带目标库），执行完关闭。
   - 修复了旧实现里 `SET SESSION sql_select_limit` 可能落在池中另一条连接上的隐患；
   - `SELECT CONNECTION_ID()` 的结果因此确定，可用于 `KILL QUERY`。
   - 代价：每次执行多一次握手（本地 2~5ms）。若远程库延迟敏感，后续可改为「每连接缓存一个执行会话」。
3. **多语句**：按 `utils/sql.rs` 切分后顺序执行（同一会话，临时表/变量可跨语句生效），遇到首个错误立即停止，已完成的语句结果保留并通过 `error: { index, sqlPreview, message }` 返回。
4. **取消**：`KILL QUERY <session_id>` 在连接的主池上执行（文本协议）。实测被中断的 `SELECT SLEEP(10)` 会**返回一行 1 而不是报错**，因此以「取消标记」为准：若语句返回时标记已置位，丢弃这条语句的结果并把整体标记为 `cancelled`。
5. **历史**：执行前写入 `running` 记录，结束后更新状态与统计；`query.history_enabled = false` 时不写入；每 20 次执行按 `query.history_limit` 清理一次旧记录。历史写入失败只告警，不影响 SQL 结果。

### 影响

- 结果面板按语句分标签，最多 200 条语句；超限直接拒绝并提示。
- 取消后返回 `cancelled=true` 且不返回错误详情，界面显示「已取消（已完成 n / m 条语句）」。
- 执行历史与 SQL 收藏共用本地 SQLite，删除连接不会删除历史。

## TDR-004 事务、窗口状态与多工作区

- **日期**：2026-11-18
- **状态**：已验证（事务行为有 MySQL 集成测试；多工作区与窗口状态需人工验证启动流程）

### 事务

- 每个查询标签可开启一个手动事务，后端使用**独立单连接池**执行 `START TRANSACTION`，事务 ID 与 `ManagedConnection` 绑定。
- 事务内的 `execute_sql` 复用该会话（因此 `SET SESSION`、临时表、行锁都连续）；取消仍通过 `KILL QUERY` 作用于该会话。
- 提交/回滚后立即关闭连接池；连接断开或应用退出时由 `close_all` 统一关闭（MySQL 自动回滚未提交内容）。
- 前端把事务状态放在 Pinia（按标签 ID），因为工作区只挂载当前标签组件，组件内状态会随切换丢失。
- **约束**：关闭标签或切换工作区会先回滚该标签的事务，避免悬挂锁。

### 窗口状态

- 使用官方 `tauri-plugin-window-state` 保存/恢复尺寸、位置与最大化状态，不自建 `window.*` 设置键。
- 理由：插件在退出时写入、启动时恢复，无需监听 resize 事件频繁写库；设置界面里也不增加无意义的数字输入。

### 多工作区

- `workspace_state` 表本身以 `state_key` 区分，多工作区直接复用；**名称存于状态 JSON 的 `name` 字段**（`#[serde(default)]`，旧数据无名称时回退「默认工作区」/工作区 ID）。
- 当前工作区 ID 存 `localStorage`（窗口级偏好），标签与布局随工作区一起保存。
- 切换流程：回滚当前事务 → `flush` 保存当前 → 切换 ID → 清空标签 → `restore` 目标工作区 → 重新拉取工作区列表。
- 默认工作区 `main` 不允许删除，避免启动时无可用状态。

## TDR-005 批量事务、内联编辑与视图偏好

- **日期**：2026-11-18
- **状态**：已验证（批量回滚有集成测试；内联编辑与偏好需人工验证交互）

### 批量变更

- 新增 `execute_batch_sql`：后端在**一条独立连接**上 `START TRANSACTION`，顺序执行语句，任一条失败即 `ROLLBACK` 并返回 `rolledBack = true`。
- 与「手动事务」区别：批量变更是一次性、自动提交/回滚，不占用标签的事务状态。
- **限制**：MySQL 的 DDL 会隐式提交，若批量里混入 DDL，原子性不再成立；界面只用于表数据的 UPDATE/DELETE，不涉及 DDL。

### 单元格内联编辑

- 双击单元格进入编辑，回车/失焦提交、Esc 取消；提交前按 `information_schema` 的类型校验（整数、decimal、日期时间、JSON、enum、varchar 长度、`tinyint(1)` 布尔写法）。
- 校验失败只提示并保留原值，不进入待保存队列；最终仍由数据库约束兜底。
- 内联编辑无法表达 NULL，需要置空请用行编辑弹窗的「置 NULL」。

### 表视图偏好

- 列顺序、显隐、列宽按 `connectionId|database|table` 存 **localStorage**（`datadock.tableView.*`，带版本号）。
- 未放入 SQLite：这些是窗口级视觉偏好，与"工作区/标签"不同，不需要跨设备同步；后续若需要可在 `app_settings` 增加前缀键。

## TDR-006 Redis 适配器（命令控制台模式）

- **日期**：2026-11-18
- **状态**：已验证（本地 Redis 8.10.3，集成测试走 `DATADOCK_REDIS_PASSWORD` 环境变量）

### 接入方式

- Redis 没有 SQL、没有表结构，也没有连接池语义，因此**不复用** `ConnectionManager`：
  新增 `RedisManager` 保存 `MultiplexedConnection`，与 MySQL 运行时并存。
- 连接配置仍写入同一张 `data_sources` 表（`source_type = 'redis'`），密码仍只进系统凭据。
- 前端在连接对话框选择类型；资源树按 `sourceType` 分发：Redis 只返回当前库（`db0`），
  不展示键（键空间浏览属后续迭代）。
- 查询标签复用：`isRedis` 时把编辑区内容当作一条 Redis 命令执行，结果映射为
  `ExecuteSqlResponse`（单结果集），因此结果网格、错误提示、导出等逻辑无需改动。

### 结果映射

- `Nil` → 空结果；`Int`/`SimpleString`/`BulkString`/`Okay` → 一行一列；
- `Array` → 单列 `value`；`HGETALL` / `CONFIG GET` 在 RESP2 下是扁平 k/v 数组，
  按命令名特判为 `field` / `value` 两列；
- `Map` → `field` / `value` 两列；嵌套数组按 `[a, b]` 文本展开。

### 边界

- 命令行解析支持单/双引号与反斜杠转义；不支持 `--` 参数提示等 shell 特性。
- Redis 命令不写查询历史、不支持取消与手动事务（命令本身可用 `MULTI/EXEC`）。
- 键空间浏览、过期时间展示、类型化编辑器（Hash/List/Set/ZSet）留待后续。

## TDR-007 浮层遮挡、表结构设计器与 SQL 日志

- **日期**：2026-11-18
- **状态**：已验证（集成测试覆盖 ALTER 语句形态与建库语句读取）

### 浮层遮挡

- 根因：`.menubar` / `.toolbar` 用了 `backdrop-filter`，会自建层叠上下文；内部 `z-index: 100` 的下拉菜单只在自身上下文有效，被右侧 `WorkspaceTabs`（同 z-index、DOM 顺序更后）盖住。
- 修复：新增通用 `AppPopover`（Teleport 到 body + `position: fixed`，按 anchor 的 `getBoundingClientRect` 定位，支持翻转/贴边约束/自动 flip）；`AppDropdown` 改为封装 `AppPopover`；菜单栏为每个菜单标题维护 DOM 引用并按其定位面板。外层裁剪容器（`overflow`）从此不影响浮层。

### 表结构设计器

- `utils/table-ddl.ts` 用纯函数生成最小 `ALTER` 集合：字段按 `ADD` / `MODIFY` / `CHANGE`（改名才用）/ `DROP` 分类，索引按 `ADD INDEX/UNIQUE INDEX/PRIMARY KEY` / `DROP INDEX` 分类；全部用反引号标识符 + 单引号转义字面量。
- 保留 `information_schema` 里的 `on update CURRENT_TIMESTAMP`（否则 `MODIFY` 会静默丢掉），`tinyint(1)` 默认 0/1 且可选 true/false。
- 界面：`StructureTab` 变为「基本信息 / 字段 / 索引 / DDL」四个子页，字段与索引都是可编辑表格，底部按「预览 → 确认 → 执行 ALTER」三段式走 `execute_sql`，历史里 `sourceType = structure`。
- **边界**：不自动改列顺序（避免 `AFTER` 语义复杂），改列名会连带触发 `MODIFY`（保证列定义不丢）；外键不处理。

### SQL 日志面板

- 新增 `stores/sql-log.ts`：**内存**数组，容量 500 条，超限丢弃最旧；不落 SQLite（查询历史已有 200 条持久化，这里是会话级调试视图）。
- 拦截点：`api/query.ts` 在 `executeSql` 调用前 push（含状态/耗时/行数/连接名/库名/结果消息），因此 Redis、结构设计器、表数据编辑都会出现在日志里。
- 入口：状态栏「SQL 日志 N」按钮、视图菜单、关闭按钮；面板按最新在上的顺序展示，可点击 SQL 复制，支持一键清空。
