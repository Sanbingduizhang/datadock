# DataDock UI 与交互设计规范

> 文档版本：V1.0
> 文档状态：设计规范
> 适用版本：V1.0（MySQL）
> 所属项目：DataDock

## 1. 设计目标

### 1.1 产品界面定位

DataDock 是一款面向开发者的桌面数据库管理工具。

整体 UI 以成熟数据库客户端的使用习惯为基础，借鉴 Navicat 的页面布局、数据库资源管理方式和数据浏览交互，同时采用现代桌面应用的视觉设计。

核心设计方向：

- Navicat 式数据库管理布局。
- Modern Desktop UI（现代桌面应用）。
- Glassmorphism（适度玻璃拟态）。
- Minimalism（简洁、克制的视觉设计）。
- Soft UI（柔和的层次与视觉反馈）。
- Native Desktop Experience（桌面原生应用体验）。

最终目标：

界面简洁、优雅、清晰，既有成熟数据库客户端的专业感，又有现代桌面软件的精致感。

不采用传统后台管理系统的页面布局，也不采用 VS Code 式 IDE 作为整体页面布局。

### 1.2 设计原则

**原则一：功能优先**

数据库管理工具最重要的是连接、查询、数据浏览和结构管理。

不能为了视觉效果影响 SQL 编辑器、数据表格和数据库资源树的使用体验。

**原则二：布局稳定**

整体布局应当保持稳定，用户打开不同数据库、切换不同标签页时，不应该频繁改变页面结构。

**原则三：信息层次清晰**

通过字体、间距、背景、边框和图标区分不同区域。

避免过多颜色、阴影、渐变和装饰性元素。

**原则四：交互符合习惯**

尽量遵循成熟数据库客户端的操作习惯，降低用户学习成本。

**原则五：视觉统一**

所有页面、弹窗、菜单、按钮、表格和状态提示必须使用统一的设计规范。

## 2. 整体页面布局

### 2.1 主界面结构

DataDock 主界面采用经典数据库客户端布局。

整体分为：

1. 顶部菜单栏。
2. 顶部工具栏。
3. 左侧数据库导航区域。
4. 中央多标签工作区。
5. 底部信息与执行结果区域。
6. 底部状态栏。

布局示意：

```
┌──────────────────────────────────────────────────────────────┐
│ DataDock    文件  编辑  查看  工具  窗口  帮助                 │
├──────────────────────────────────────────────────────────────┤
│ 新建连接  打开SQL  执行  停止  提交  回滚  刷新  设置          │
├──────────────┬───────────────────────────────────────────────┤
│              │                                               │
│  数据源      │  SQL查询 | users表 | orders表                  │
│              ├───────────────────────────────────────────────┤
│  MySQL连接1  │                                               │
│   ├ 数据库A  │                                               │
│   │ ├ Tables │              中央工作区域                     │
│   │ ├ Views  │                                               │
│   │ └ ...    │                                               │
│   └ 数据库B  │                                               │
│              │                                               │
│  MySQL连接2  │                                               │
│              ├───────────────────────────────────────────────┤
│              │  结果 | 消息 | 执行日志                         │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 已连接 | MySQL | 连接名称 | 执行状态 | 行数 | 耗时             │
└──────────────────────────────────────────────────────────────┘
```

以上是结构示意，不是最终视觉稿。

AI 实现时应当以实际组件和窗口尺寸为准，保证布局能够自适应。

### 2.2 布局尺寸建议

以下尺寸作为 V1.0 默认建议值，可以根据实际 UI 效果调整。

| 区域                 | 建议尺寸   |
| -------------------- | ---------- |
| 顶部菜单栏           | 32px       |
| 顶部工具栏           | 44px       |
| 左侧导航栏           | 默认 250px |
| 左侧导航最小宽度     | 180px      |
| 左侧导航最大宽度     | 420px      |
| 底部结果区域         | 默认 220px |
| 底部结果区域最小高度 | 100px      |
| 状态栏               | 24px       |
| 标签栏               | 36px       |

要求：

- 左侧导航栏可以拖动调整宽度。
- 底部结果区域可以拖动调整高度。
- 中央工作区自动占据剩余空间。
- 窗口缩放时不能出现内容溢出。
- 支持合理的最小窗口尺寸。
- 用户调整后的面板尺寸可以保存在本地工作区状态中。

建议默认窗口尺寸为 1440 × 900，最低支持尺寸建议为 1100 × 700。

## 3. 顶部菜单栏

### 3.1 菜单结构

顶部菜单栏采用桌面应用常见菜单结构。

建议包含：

| 菜单   | 功能                                     |
| ------ | ---------------------------------------- |
| 文件   | 新建连接、打开 SQL 文件、保存 SQL、退出  |
| 编辑   | 撤销、重做、剪切、复制、粘贴、查找、替换 |
| 查看   | 显示或隐藏导航栏、结果面板、状态栏       |
| 数据库 | 连接、断开、刷新、选择数据库             |
| SQL    | 执行当前语句、执行全部、停止执行、格式化 |
| 工具   | 设置、查询历史、SQL 收藏                 |
| 窗口   | 切换工作区标签、关闭标签                 |
| 帮助   | 关于 DataDock、版本信息                  |

### 3.2 菜单交互

- 点击菜单名称展开下拉菜单。
- 点击菜单外部关闭菜单。
- 支持菜单项禁用状态。
- 支持快捷键提示。
- 支持合理的二级菜单。
- 菜单风格与整体主题保持一致。

## 4. 顶部工具栏

### 4.1 工具栏功能

顶部工具栏用于放置高频操作。

建议包含：

- 新建连接。
- 打开 SQL 文件。
- 保存 SQL 文件。
- 执行 SQL。
- 停止执行。
- 提交事务。
- 回滚事务。
- 刷新。
- 设置。

根据当前工作区和连接状态动态启用或禁用对应操作。

例如：

- 没有活动连接时，执行按钮不可用。
- SQL 正在执行时，执行按钮可以根据执行策略禁用，停止按钮启用。
- 当前连接不支持某项操作时，不应展示为可用状态。

### 4.2 工具栏视觉要求

- 使用轻量级背景。
- 图标统一，建议使用 Lucide 图标库。
- 按钮采用简洁的图标按钮或图标加文字形式。
- 鼠标悬停时提供提示。
- 当前不可用的操作需要有明确的禁用状态。
- 不使用过多彩色按钮。
- 执行、停止等高频操作可以适当突出。

工具栏可以采用轻度玻璃拟态效果，但必须保证图标和文字清晰。

## 5. 左侧数据库导航区域

### 5.1 功能定位

左侧区域用于管理所有数据库连接和数据库对象。

这是 DataDock 的核心导航区域之一。

用户可以在这里：

- 创建数据库连接。
- 编辑数据库连接。
- 删除数据库连接。
- 建立或断开连接。
- 展开数据库。
- 查看数据库对象。
- 打开表数据。
- 查看表结构。
- 打开视图等数据库对象。

### 5.2 资源树结构

V1.0 主要支持 MySQL。

建议结构：

```
数据源
├── MySQL-开发环境
│   ├── database_a
│   │   ├── Tables
│   │   │   ├── users
│   │   │   ├── orders
│   │   │   └── products
│   │   ├── Views
│   │   ├── Functions
│   │   └── Procedures
│   │
│   └── database_b
│       ├── Tables
│       └── Views
│
└── MySQL-测试环境
    └── database_c
```

实际展示的对象应当以数据库中真实存在的对象为准。

V1.0 优先实现：

- 数据源连接。
- 数据库。
- Tables。
- Views。

Functions 和 Procedures 可以根据实际实现进度完善。

### 5.3 资源树交互

数据源节点：

- 单击可以选中。
- 双击可以连接或断开，具体行为应结合当前连接状态。
- 右键打开操作菜单。
- 展开节点时按需加载数据库信息。
- 支持刷新。

数据库节点：

- 展开时加载数据库对象。
- 双击数据库可以打开数据库工作区或默认对象视图。
- 右键可以刷新、设置为当前数据库等。

表节点：

- 双击打开表数据。
- 右键打开操作菜单。
- 支持查看表数据。
- 支持查看表结构。
- 支持复制表名。
- 支持刷新表信息。

### 5.4 右键菜单

连接节点：

- 连接。
- 断开连接。
- 编辑连接。
- 新建 SQL 查询。
- 刷新。
- 删除连接。

数据库节点：

- 设置为当前数据库。
- 刷新。
- 新建 SQL 查询。
- 复制数据库名称。

表节点：

- 打开表数据。
- 查看表结构。
- 查看建表 SQL。
- 刷新。
- 复制表名。

### 5.5 资源树视觉要求

- 使用统一的图标体系。
- 不同数据库对象使用不同图标。
- 当前选中节点需要有明确的背景反馈。
- 悬停时显示轻量背景反馈。
- 展开和收起需要有简单过渡。
- 节点名称过长时采用省略显示，悬停展示完整名称。
- 连接状态需要通过图标或状态标识清晰表达。
- 不使用过于复杂的树节点装饰。

### 5.6 加载与异常状态

需要考虑：

- 正在加载。
- 加载成功。
- 加载失败。
- 当前节点为空。
- 连接已经断开。
- 数据库对象发生变化。

加载失败时应提供可理解的错误信息和重试入口，不能让资源树一直处于加载状态。

## 6. 中央多标签工作区

### 6.1 功能定位

中央工作区是用户主要操作区域。

采用多标签方式管理不同的工作内容。

V1.0 至少支持以下标签类型：

1. SQL 查询。
2. 表数据。
3. 表结构。
4. 建表 SQL。

### 6.2 标签栏

标签栏位于中央工作区顶部。

标签内容建议包含：

- 图标。
- 标签名称。
- 未保存状态标识。
- 关闭按钮。

交互要求：

- 单击标签切换工作区。
- 双击标签可以根据实际体验实现重命名或其他合理行为。
- 点击关闭按钮关闭标签。
- 支持关闭当前标签。
- 支持关闭其他标签。
- 支持关闭右侧标签。
- 支持关闭全部标签。
- 未保存 SQL 关闭前需要提示保存。
- 标签数量较多时支持横向滚动。

标签名称建议：

| 类型     | 示例         |
| -------- | ------------ |
| SQL 查询 | SQL 查询 1   |
| 表数据   | users        |
| 表结构   | users - 结构 |
| 建表 SQL | users - DDL  |

### 6.3 标签与连接关系

每个工作区需要明确关联的数据源和数据库上下文。

例如：

- SQL 查询标签关联某个数据源连接。
- 表数据标签关联某个数据源、数据库和表。
- 表结构标签关联某个数据源、数据库和表。

切换标签时不能错误地使用其他标签的数据库连接。

同一张表是否复用已有标签，可以采用合理的默认策略。

建议：

同一连接下，同一张表重复打开时优先定位到已有标签，避免产生大量重复工作区。

## 7. SQL 编辑器界面

### 7.1 编辑器定位

SQL 编辑器是 DataDock 的核心功能。

建议使用 Monaco Editor 实现。

Monaco Editor 是建议方案，最终依赖需要在技术架构文档中确认。

### 7.2 编辑器布局

```
┌───────────────────────────────────────────────┐
│ SQL 查询 1                      保存 | 执行    │
├───────────────────────────────────────────────┤
│ 连接：MySQL-开发环境    数据库：database_a     │
├───────────────────────────────────────────────┤
│                                               │
│  1  SELECT *                                  │
│  2  FROM users                                │
│  3  WHERE status = 1;                         │
│                                               │
│                                               │
├───────────────────────────────────────────────┤
│ 结果 | 消息 | 执行日志                         │
│                                               │
└───────────────────────────────────────────────┘
```

### 7.3 编辑器基本功能

V1.0 需要支持：

- SQL 语法高亮。
- 行号。
- 自动缩进。
- 括号匹配。
- 代码折叠。
- 查找。
- 替换。
- 多行编辑。
- 基础 SQL 自动补全。
- SQL 格式化。
- SQL 文件打开和保存。
- 多 SQL 标签。

### 7.4 SQL 执行操作

支持：

- 执行当前语句。
- 执行选中 SQL。
- 执行全部 SQL。
- 停止执行。

执行行为：

- 当前语句执行时，应当识别光标所在的 SQL 语句。
- 有选中内容时，执行选中内容。
- 没有选中内容时，根据执行命令执行当前语句或全部 SQL。
- 执行过程中显示执行状态。
- 执行完成后展示结果或错误信息。
- SQL 执行不能阻塞整个应用界面。

具体语句解析和执行规则需要在核心模块设计文档中定义。

### 7.5 编辑器视觉要求

- 编辑区域保持干净。
- 代码字体采用等宽字体。
- 行号颜色弱化。
- 当前行提供轻量高亮。
- 语法颜色在深色和浅色主题下保持足够对比度。
- 编辑区域不使用过度透明背景。
- 不使用大量装饰性边框。

SQL 编辑器应当优先保证可读性和长时间使用的舒适度。

## 8. SQL 查询结果区域

### 8.1 区域定位

查询结果区域位于 SQL 编辑器下方。

建议采用可拖动调整高度的面板。

内部采用标签结构：

- 结果。
- 消息。
- 执行日志。

### 8.2 结果标签

用于展示 SQL 查询返回的数据。

基本要求：

- 表格形式展示。
- 支持横向滚动。
- 支持纵向滚动。
- 列宽合理。
- 支持复制单元格内容。
- 支持复制整行。
- 支持复制选中数据。
- 支持查看较长字段内容。
- 支持 NULL 值的明确展示。
- 支持空结果提示。

查询结果可能包含多个结果集，需要能够区分不同结果集。

如果一次执行包含多条查询语句，应当根据实际执行结果展示对应结果。

### 8.3 消息标签

展示执行过程中的信息，例如：

- 执行成功。
- 影响行数。
- 执行耗时。
- SQL 错误。
- 数据库返回的提示信息。

### 8.4 执行日志标签

展示本次执行的过程信息。

建议包括：

- SQL 内容。
- 执行开始时间。
- 执行结束时间。
- 执行耗时。
- 执行状态。
- 错误信息。

日志内容不应影响正常结果展示。

### 8.5 结果区域交互

- 可以拖动分隔线调整高度。
- 支持折叠和展开。
- 查询结束后自动切换到适当的结果标签。
- 执行失败时可以自动定位到消息区域。
- 查询结果较多时应采用分页或分批获取机制。
- 不应一次性将大量结果全部加载到前端。

具体数据量限制由产品配置和 SQL 执行模块共同决定。

## 9. 表数据浏览界面

### 9.1 功能定位

表数据浏览是数据库客户端最常用的功能之一。

用户可以通过资源树双击表节点进入表数据页面。

### 9.2 页面布局

```
┌────────────────────────────────────────────────────┐
│ users                                               │
├────────────────────────────────────────────────────┤
│ 刷新 | 新增 | 编辑 | 删除 | 提交 | 导出             │
├────────────────────────────────────────────────────┤
│ 筛选条件                                            │
├────────────────────────────────────────────────────┤
│ id  | username | email          | status | created  │
│ 1   | admin    | admin@test.com | 1      | ...      │
│ 2   | user     | user@test.com  | 1      | ...      │
│ 3   | test     | test@test.com  | 0      | ...      │
├────────────────────────────────────────────────────┤
│ 共 1000 条      每页 100 条       1  2  3  下一页   │
└────────────────────────────────────────────────────┘
```

### 9.3 工具栏功能

- 刷新。
- 新增记录。
- 编辑记录。
- 删除记录。
- 保存修改。
- 取消修改。
- 导出数据。

根据当前数据库能力和数据状态控制按钮。

### 9.4 数据表格

要求：

- 支持横向滚动。
- 支持纵向滚动。
- 表头固定。
- 列宽可调整。
- 支持排序。
- 支持分页。
- 支持单元格复制。
- 支持行选择。
- 支持字段内容查看。
- 支持不同数据类型的合理展示。

NULL 值和空字符串必须能够明确区分。

对于 BLOB、JSON、TEXT 等特殊字段，应根据字段类型提供合适的展示方式。

### 9.5 数据编辑

V1.0 支持：

- 新增记录。
- 修改记录。
- 删除记录。
- 保存修改。
- 取消修改。

编辑要求：

- 修改前应保留原始值。
- 用户取消修改时恢复原始值。
- 保存失败时保留编辑内容。
- 删除操作需要二次确认。
- 修改成功后刷新或更新当前数据。
- 对可能影响多条记录的操作提供明确提示。

对于没有主键或唯一键的表，必须谨慎处理更新和删除。

不能假设任意表都可以安全地通过普通行号定位记录。

### 9.6 分页

默认每页建议 100 条。

建议提供：

- 50 条。
- 100 条。
- 200 条。
- 500 条。

分页需要支持：

- 上一页。
- 下一页。
- 跳转指定页。
- 修改每页条数。
- 显示总记录数（能够可靠获取时）。

不应为了展示总数而对大型表执行不必要的高成本统计查询。

### 9.7 筛选与排序

V1.0 提供基础筛选和排序。

筛选需要支持常见条件：

- 等于。
- 不等于。
- 包含。
- 不包含。
- 大于。
- 小于。
- 大于等于。
- 小于等于。
- IS NULL。
- IS NOT NULL。

不同字段类型可以展示不同的筛选操作。

筛选条件应当使用参数化查询，不能直接拼接用户输入形成不安全 SQL。

排序应当正确处理字段名转义和排序方向。

## 10. 表结构查看界面

### 10.1 功能定位

用户通过表结构页面查看当前表的定义。

V1.0 以查看为主，复杂结构修改可以后续实现。

### 10.2 页面结构

建议采用标签或分区形式：

- 字段。
- 索引。
- 建表 SQL。

### 10.3 字段信息

字段列表至少展示：

| 字段    | 说明          |
| ------- | ------------- |
| Field   | 字段名称      |
| Type    | 字段类型      |
| Null    | 是否允许 NULL |
| Key     | 键类型        |
| Default | 默认值        |
| Extra   | 额外属性      |
| Comment | 字段注释      |

具体字段信息以 MySQL 实际返回的数据为准。

### 10.4 索引信息

展示：

- 索引名称。
- 索引类型。
- 索引字段。
- 是否唯一。
- 是否主键。

### 10.5 建表 SQL

提供建表 SQL 查看功能。

要求：

- 使用代码编辑器展示。
- SQL 语法高亮。
- 支持复制。
- 支持保存为 SQL 文件。

V1.0 不要求直接通过页面修改表结构。

## 11. 数据源连接界面

### 11.1 新建连接

用户点击新建连接后打开连接配置窗口。

建议采用独立弹窗。

MySQL 连接表单包含：

| 配置项     | 说明                 |
| ---------- | -------------------- |
| 连接名称   | 用户自定义名称       |
| 主机地址   | 数据库服务器地址     |
| 端口       | 默认 3306            |
| 用户名     | 数据库用户名         |
| 密码       | 数据库密码           |
| 默认数据库 | 可选                 |
| 字符集     | 根据驱动支持情况提供 |
| 连接超时   | 可配置或使用默认值   |

连接名称只是本地展示名称，不一定等于数据库名称。

### 11.2 连接操作

提供：

- 测试连接。
- 保存连接。
- 取消。

测试连接应当显示：

- 测试中。
- 连接成功。
- 连接失败。
- 错误原因。

连接失败时，应提供明确错误信息。

### 11.3 编辑连接

允许修改已有连接配置。

密码为空时，不应默认覆盖原有密码。

需要通过明确的密码修改行为更新凭据。

### 11.4 删除连接

删除前进行确认。

删除连接后：

- 关闭对应活动连接。
- 清理对应系统凭据。
- 删除本地连接配置。
- 保留历史查询记录。
- 保留 SQL 收藏。

删除连接不能误删远程数据库中的数据。

## 12. 查询历史与 SQL 收藏界面

### 12.1 查询历史

建议作为独立页面或侧边弹出面板。

展示内容：

- SQL 内容。
- 所属连接。
- 所属数据库。
- 执行时间。
- 执行状态。
- 执行耗时。

支持：

- 查看 SQL。
- 复制 SQL。
- 重新打开 SQL。
- 按连接筛选。
- 按时间筛选。
- 搜索 SQL 内容。

历史记录仅保存在本地。

### 12.2 SQL 收藏

用户可以将常用 SQL 保存到收藏。

支持：

- 添加收藏。
- 编辑收藏名称。
- 修改 SQL。
- 删除收藏。
- 复制 SQL。
- 打开到 SQL 编辑器。

建议支持收藏分类，但 V1.0 可以先采用简单列表实现。

## 13. 弹窗与浮层规范

### 13.1 弹窗类型

统一管理以下弹窗：

- 新建连接。
- 编辑连接。
- 删除确认。
- SQL 文件保存。
- SQL 文件打开。
- 设置。
- 关于 DataDock。
- 大字段内容查看。
- 错误详情。

### 13.2 弹窗设计原则

- 居中显示。
- 合理控制宽度。
- 内容过多时支持内部滚动。
- 主操作按钮位置统一。
- 取消按钮使用次要样式。
- 危险操作使用明确的警示样式。
- 点击遮罩是否关闭应根据弹窗类型决定。
- 重要操作不能因为点击遮罩而意外丢失数据。

### 13.3 玻璃拟态效果

弹窗、菜单和浮层可以采用适度玻璃拟态。

要求：

- 背景模糊程度适中。
- 弹窗内容清晰。
- 边框和阴影轻量。
- 不使用过度透明背景。
- 不影响输入框和按钮的识别。

如果系统或运行环境不支持背景模糊，应自动降级为不透明背景。

## 14. 视觉设计规范

### 14.1 整体风格

DataDock 应当呈现现代、精致、克制的桌面软件风格。

关键词：

- Elegant。
- Minimal。
- Modern。
- Clean。
- Professional。
- Soft。
- Glassmorphism。

不希望出现：

- 传统后台管理系统风格。
- 大量卡片堆叠。
- 过度圆角。
- 过度渐变。
- 过多彩色按钮。
- 过度阴影。
- 大面积透明导致内容难以阅读。
- 过多装饰性图标。

### 14.2 圆角规范

建议：

| 组件     | 圆角 |
| -------- | ---- |
| 小按钮   | 5px  |
| 输入框   | 6px  |
| 普通卡片 | 8px  |
| 弹窗     | 12px |
| 下拉菜单 | 8px  |
| 浮动面板 | 10px |

整体保持轻量，避免所有组件都使用过大的圆角。

### 14.3 间距规范

建议使用 4px 基础间距体系。

常见间距：

- 4px：紧凑元素间距。
- 8px：普通元素间距。
- 12px：组件内部间距。
- 16px：常规区域间距。
- 24px：模块之间间距。
- 32px：较大的区域间距。

不同页面应尽量保持一致。

### 14.4 字体规范

优先使用系统原生字体。

建议：

- 中文：系统默认中文字体。
- 英文：系统默认无衬线字体。
- SQL 编辑器：等宽字体。
- 数据表格：清晰易读的常规字体。

字号建议：

| 场景     | 字号 |
| -------- | ---- |
| 主菜单   | 13px |
| 工具栏   | 13px |
| 导航树   | 13px |
| 表格内容 | 13px |
| 普通正文 | 14px |
| 弹窗标题 | 16px |
| 页面标题 | 16px |
| 辅助信息 | 12px |

不应使用过小字体承载重要信息。

### 14.5 图标规范

建议统一使用 Lucide 图标库。

要求：

- 图标风格统一。
- 线条粗细统一。
- 图标尺寸统一。
- 常规图标建议 16px。
- 主要工具栏图标建议 18px。
- 不混用大量不同风格的图标。
- 图标必须与实际操作含义一致。

## 15. 主题设计

### 15.1 主题模式

V1.0 支持：

- 浅色主题。
- 深色主题。
- 跟随系统。

默认建议跟随系统。

### 15.2 浅色主题

浅色主题要求：

- 整体背景明亮。
- 内容区域层次清晰。
- 边框轻量。
- 表格线条清晰但不过重。
- 文字具有足够对比度。
- 适当使用柔和背景色。

### 15.3 深色主题

深色主题要求：

- 避免纯黑背景。
- 使用不同深浅的背景区分区域。
- SQL 语法颜色清晰。
- 表格文字容易阅读。
- 选中状态清楚。
- 边框不应过亮。

### 15.4 主题一致性

所有组件必须支持主题切换，包括：

- 菜单。
- 工具栏。
- 导航树。
- SQL 编辑器。
- 数据表格。
- 结果面板。
- 弹窗。
- 下拉菜单。
- 提示信息。
- 状态栏。

不能只切换页面背景，而忽略内部组件。

## 16. 玻璃拟态设计规范

### 16.1 使用范围

玻璃拟态是 DataDock 的视觉特色之一，但不应当滥用。

建议用于：

- 顶部工具栏。
- 菜单。
- 下拉菜单。
- 弹窗。
- 浮动面板。
- 提示面板。
- 部分轻量悬浮控件。

### 16.2 不建议使用的区域

以下区域优先保证可读性：

- SQL 编辑器代码区域。
- 数据表格。
- 查询结果。
- 数据库资源树主体。
- 大量文字内容区域。

### 16.3 视觉要求

适度使用：

- 半透明背景。
- 背景模糊。
- 细边框。
- 柔和阴影。
- 轻微高光。

不要使用：

- 极高透明度。
- 强烈背景模糊。
- 过多发光效果。
- 大面积渐变。
- 多层玻璃叠加。

最终效果应当是精致、通透，而不是花哨。

## 17. 交互反馈规范

### 17.1 按钮状态

按钮需要支持：

- 默认状态。
- 悬停状态。
- 按下状态。
- 禁用状态。
- 加载状态。

所有可点击元素都应提供明确反馈。

### 17.2 加载状态

以下操作需要有加载反馈：

- 测试连接。
- 建立数据库连接。
- 加载数据库列表。
- 加载表结构。
- 查询数据。
- 执行 SQL。
- 导出数据。

加载状态应避免重复点击造成重复操作。

### 17.3 成功提示

操作成功时，可以使用轻量 Toast 提示。

例如：

- 连接成功。
- SQL 执行成功。
- 数据保存成功。
- SQL 已复制。
- 文件保存成功。

提示不应长时间遮挡操作区域。

### 17.4 错误提示

错误提示需要：

- 简洁说明发生了什么。
- 尽可能提供可理解的原因。
- 必要时提供详细信息入口。
- 不应只显示“操作失败”。
- 不应直接向普通用户展示难以理解的内部异常堆栈。

### 17.5 危险操作

以下操作需要确认：

- 删除数据库连接。
- 删除数据记录。
- 执行可能影响大量数据的操作。
- 关闭包含未保存 SQL 的标签。

确认弹窗应说明操作对象和潜在影响。

不能因为用户确认删除本地连接，就自动删除远程数据库。

## 18. 快捷键规范

V1.0 建议支持以下快捷键。

| 快捷键                   | 操作          |
| ------------------------ | ------------- |
| Cmd/Ctrl + N             | 新建连接      |
| Cmd/Ctrl + O             | 打开 SQL 文件 |
| Cmd/Ctrl + S             | 保存 SQL 文件 |
| Cmd/Ctrl + F             | 查找          |
| Cmd/Ctrl + H             | 替换          |
| Cmd/Ctrl + Enter         | 执行当前 SQL  |
| Cmd/Ctrl + Shift + Enter | 执行全部 SQL  |
| Cmd/Ctrl + W             | 关闭当前标签  |
| Cmd/Ctrl + R             | 刷新当前视图  |
| Cmd/Ctrl + ,             | 打开设置      |

说明：

- macOS 使用 Command。
- Windows 和 Linux 使用 Control。
- 快捷键不能与系统级快捷键产生明显冲突。
- 快捷键需要根据当前焦点合理处理。
- SQL 编辑器内的快捷键优先遵循编辑器习惯。

## 19. 空状态设计

所有主要模块都应当设计空状态。

### 19.1 没有数据库连接

展示：

- 简洁的空状态图标。
- 提示用户尚未创建数据库连接。
- 新建连接入口。

### 19.2 没有数据库

提示当前连接中没有可展示的数据库，或者当前用户没有查看权限。

### 19.3 没有查询结果

区分：

- SQL 查询成功，但没有返回记录。
- 当前表没有数据。
- 当前筛选条件没有匹配记录。

不能将这些状态混为一谈。

### 19.4 没有查询历史

提示暂无查询历史，并说明执行 SQL 后会自动记录。

### 19.5 没有 SQL 收藏

提供添加 SQL 收藏的操作入口。

## 20. 响应式与窗口适配

DataDock 是桌面应用，优先适配桌面窗口，而不是传统移动端网页。

需要支持：

- macOS。
- Windows。
- Linux（以实际 Tauri 构建支持情况为准）。

适配要求：

- 窗口放大时中央工作区能够扩展。
- 窗口缩小时合理压缩布局。
- 左侧导航栏可以收起。
- 底部结果区域可以折叠。
- 表格支持横向滚动。
- 菜单和弹窗不能超出可视窗口。
- 不同系统的窗口装饰和菜单行为需要合理适配。

V1.0 不要求移动端布局。

## 21. 动效规范

动效应当轻量、克制。

建议：

| 场景     | 建议时长 |
| -------- | -------- |
| 按钮悬停 | 100ms    |
| 菜单展开 | 120ms    |
| 弹窗出现 | 160ms    |
| 标签切换 | 100ms    |
| 面板展开 | 160ms    |

要求：

- 动画不能影响操作效率。
- 不使用复杂的页面转场。
- 不使用大范围弹跳效果。
- 支持系统减少动态效果的偏好。
- 动画失败或被禁用时不影响功能。

## 23. UI 实现约束

2. 不得将整体界面设计成 VS Code 式 IDE。
3. 不得使用传统后台管理系统布局。
4. 左侧必须具备数据库资源树。
5. 中央必须支持多标签工作区。
6. SQL 编辑器和表数据浏览必须是核心页面。
7. 底部必须具备查询结果和执行消息区域。
8. 必须支持深色和浅色主题。
9. 必须考虑玻璃拟态视觉效果，但不能牺牲可读性。
10. 必须统一组件风格、字体、间距、圆角和图标。
11. 所有操作都必须有真实功能，不能只实现静态 UI。
12. 所有异步操作必须有加载、成功和失败反馈。
13. 不得使用大量无意义的卡片填充页面。
14. 不得随意添加未在产品需求中定义的复杂功能。
15. 不得使用 Navicat 的商标、专有图标、产品素材或其他受保护的视觉资产。

## 25. 最终设计要求

DataDock 的 UI 设计必须坚持以下方向：

**以 Navicat 为交互和布局参考，以现代桌面应用为视觉目标，以玻璃拟态作为适度的视觉特色。**

产品不能只是一款能执行 SQL 的简单工具，而应该是一款拥有完整数据库客户端体验的软件。

界面需要做到：

- 第一眼简洁、漂亮。
- 长时间使用舒适。
- 高频操作方便。
- 数据展示清晰。
- 复杂功能不显得杂乱。
- 深色和浅色主题都有较好的视觉效果。

最终视觉效果应当是成熟、优雅、现代、专业，而不是简单堆叠组件形成的普通管理页面。
