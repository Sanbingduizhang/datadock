# DataDock 产品需求文档（PRD）

**文档版本：** V1.1
**产品名称：** DataDock
**产品定位：** 轻量级跨平台多数据源管理工具
**当前开发版本：** V1.0 - MySQL
**主要界面参考：** Navicat
**文档状态：** 产品需求定义

# 1. 产品概述

## 1.1 产品介绍

DataDock 是一款面向软件开发者的桌面多数据源管理工具。

用户可以通过 DataDock 统一管理不同类型的数据源，完成数据库连接、数据浏览、SQL 查询、数据编辑和数据库结构查看等日常开发工作。

第一版主要围绕 MySQL 数据库展开，建立完整的数据库客户端基础能力。

后续逐步扩展 Redis 和 PostgreSQL。

## 1.2 产品目标

V1.0 需要实现一个可以实际投入日常开发使用的 MySQL 数据库管理客户端。

核心目标：

1. 支持多个 MySQL 数据库连接。
2. 支持数据库及表结构浏览。
3. 提供完整的 SQL 编辑和执行环境。
4. 提供表数据浏览和编辑能力。
5. 提供查询结果展示和数据导出能力。
6. 提供查询历史和本地配置管理。
7. 提供符合专业数据库客户端使用习惯的操作体验。
8. 具备精致、优雅、现代化的视觉设计。

## 1.3 目标平台

- macOS
- Windows
- Linux

需要考虑不同操作系统的窗口样式、字体渲染、系统主题和窗口交互差异。

## 1.4 产品设计定位

DataDock 不采用传统后台管理系统的页面布局，也不采用以代码编辑器为中心的 VS Code 式 IDE 布局。

产品主要参考 Navicat 的数据库客户端设计理念。

重点借鉴：

- 数据库连接列表的组织方式。
- 左侧数据库对象导航。
- 顶部工具栏布局。
- 中央多标签工作区。
- 数据表格展示方式。
- 表结构与数据浏览切换方式。
- 查询编辑器与结果区域布局。
- 右键菜单和上下文操作。
- 数据库对象的管理习惯。

在此基础上重新设计 DataDock 的视觉语言和交互细节。

注意：参考 Navicat 的产品体验和布局逻辑，不直接复制其品牌标识、专有图标、产品素材或具体视觉资产。DataDock 应具有自己的品牌辨识度。

# 2. UI 与视觉设计总要求

本章节是 DataDock 的重要产品要求，优先级较高。

## 2.1 核心设计理念

**简洁不简单，精致而不繁杂。**

DataDock 应当是一款让用户第一眼就愿意使用的桌面软件。

设计不能只考虑功能能否实现，还必须重视整体视觉品质、交互体验和细节。

设计目标：

- 界面简洁，但不能显得简陋。
- 功能丰富，但不能显得拥挤。
- 视觉精致，但不能过度装饰。
- 操作直观，不需要用户反复寻找功能。
- 视觉统一，不同模块不能各自采用不同的设计风格。
- 适合长时间使用，不产生明显的视觉疲劳。

## 2.2 主要参考对象

主要参考 Navicat 的整体界面布局和数据库操作体验。

参考重点：

1. 左侧连接导航栏。
2. 数据库对象树。
3. 顶部功能工具栏。
4. 中央标签页工作区。
5. 数据浏览表格。
6. 表结构管理界面。
7. SQL 查询编辑器。
8. 查询结果区域。
9. 右键上下文菜单。
10. 数据库对象之间的导航关系。

不要将页面设计成传统的管理后台。

不要将所有操作都放进独立的弹窗中。

不要将数据库客户端设计成只有一个 SQL 编辑器的工具。

## 2.3 视觉风格

采用现代化桌面软件设计风格。

建议结合以下设计理念：

- Modern Desktop UI：现代桌面应用设计。
- Glassmorphism：适度玻璃拟态。
- Minimalism：简约设计。
- Soft UI：柔和的界面层次。
- Native Desktop Experience：符合桌面应用操作习惯。

最终效果应当是专业、精致、轻盈、优雅，而不是刻意追求炫酷。

## 2.4 Glassmorphism 玻璃拟态设计

DataDock 允许并鼓励适度使用玻璃拟态设计。

玻璃拟态主要用于提升界面的层次感和现代感。

建议使用场景：

- 顶部工具栏。
- 浮动工具面板。
- 弹出式菜单。
- 下拉菜单。
- 连接配置弹窗。
- 轻量级提示面板。
- 部分设置面板。
- 侧边浮动操作区域。

设计效果：

- 半透明背景。
- 适度背景模糊。
- 柔和边框。
- 细腻的阴影。
- 适度的背景层次。
- 自然的透明度过渡。

设计限制：

1. 不允许整个应用所有区域都使用高透明度。
2. 不允许为了玻璃效果牺牲文字可读性。
3. 数据表格必须优先保证内容清晰。
4. SQL 编辑器必须保证代码对比度。
5. 弹窗背景必须保证表单和文字清晰。
6. 不允许大量使用强烈发光效果。
7. 不允许过度使用渐变。
8. 不允许让背景装饰干扰用户操作。

玻璃效果应当是设计细节，而不是界面的主体。

在不支持背景模糊的系统环境中，应提供合适的不透明背景降级方案。

## 2.5 深色与浅色主题

必须支持两套完整主题。

### 浅色主题

整体采用干净、明亮、柔和的设计。

建议方向：

- 背景采用柔和的浅色，而非所有区域纯白。
- 面板采用白色或接近白色的背景。
- 边框采用低对比度灰色。
- 文字采用深灰色。
- 强调色适度使用蓝色或其他品牌色。
- 阴影柔和。
- 选中状态清晰但不刺眼。

### 深色主题

整体采用现代深色桌面软件风格。

建议方向：

- 主背景采用深灰或深蓝灰。
- 工作面板采用略浅的深色。
- 边框采用低对比度深灰。
- 文字采用柔和的浅灰色。
- 强调色保持统一。
- 选中状态具有明显辨识度。
- 避免大面积纯黑造成视觉压迫。

### 主题切换

支持：

- 浅色模式。
- 深色模式。
- 跟随系统。

主题切换后，所有模块必须保持视觉一致。

不能出现某些弹窗使用深色主题，而其他页面仍然是浅色主题的情况。

## 2.6 字体和图标

字体要求：

- 优先使用系统原生字体。
- 中文字体显示清晰。
- 英文字母和数字显示协调。
- SQL 编辑器使用等宽字体。
- 数据表格字体应清晰易读。

图标要求：

- 使用统一风格的图标。
- 优先采用线性图标。
- 图标尺寸和笔画保持一致。
- 避免大量使用 Emoji 作为功能图标。
- 避免同一个功能在不同页面使用不同图标。

建议采用 Lucide 图标体系。

## 2.7 动效

适度使用细腻的交互动效。

包括：

- 标签页切换。
- 菜单展开。
- 弹窗打开和关闭。
- 数据加载。
- 按钮悬停。
- 侧边栏展开和折叠。
- 主题切换。

要求：

- 动效自然。
- 速度适中。
- 不影响操作效率。
- 不允许为了视觉效果加入大量无意义动画。
- 尊重操作系统的减少动态效果设置。

## 2.8 页面设计质量要求

AI 在开发 UI 时，不能仅仅以功能实现为验收标准。

每个页面还必须满足：

1. 整体布局协调。
2. 控件对齐统一。
3. 间距规范。
4. 字体层级清晰。
5. 图标风格统一。
6. 颜色搭配合理。
7. 空状态设计完整。
8. 加载状态设计完整。
9. 错误状态设计完整。
10. 交互反馈清晰。

不得直接使用组件库默认样式拼凑整个应用。

组件库可以作为基础，但必须进行统一的主题定制和视觉设计。

# 3. 产品整体结构

## 3.1 主界面布局

DataDock 采用 Navicat 式数据库客户端布局。

主要区域：

1. 顶部菜单栏。
2. 顶部工具栏。
3. 左侧数据库导航区域。
4. 中央多标签工作区。
5. 底部信息与执行结果区域。
6. 状态栏。

整体布局示意：

```
┌──────────────────────────────────────────────────────────────┐
│ DataDock       文件  编辑  视图  工具  窗口  帮助              │
├──────────────────────────────────────────────────────────────┤
│ 新建连接  打开连接  查询  表  视图  用户  刷新  设置           │
├───────────────┬──────────────────────────────────────────────┤
│               │                                              │
│  连接导航      │  [连接1] [users] [SQL查询1] [orders]          │
│               ├──────────────────────────────────────────────┤
│  MySQL        │                                              │
│  ├─本地开发   │                                              │
│  │ ├─db_user │               数据工作区                      │
│  │ │ ├Tables │                                              │
│  │ │ └Views  │                                              │
│  │ └db_order│                                              │
│  ├─测试环境   │                                              │
│  └─生产环境   │                                              │
│               │                                              │
│               ├──────────────────────────────────────────────┤
│               │ 数据 | 结构 | 信息 | 查询结果                 │
├───────────────┴──────────────────────────────────────────────┤
│ 已连接 | MySQL | db_user                        就绪          │
└──────────────────────────────────────────────────────────────┘
```

这是逻辑布局，不是最终视觉稿。

具体布局可以根据 Navicat 的实际使用体验进行进一步优化。

## 3.2 顶部菜单栏

包含：

- 文件。
- 编辑。
- 视图。
- 工具。
- 窗口。
- 帮助。

菜单项根据实际功能逐步完善。

## 3.3 顶部工具栏

提供常用操作入口。

包括：

- 新建连接。
- 连接管理。
- 新建查询。
- 新建表。
- 刷新。
- 数据导入。
- 数据导出。
- 设置。

根据当前工作区和选择对象动态调整可用操作。

不需要将所有功能都放到工具栏中。

## 3.4 左侧导航区域

主要展示：

- 数据源连接。
- 数据库。
- 表。
- 视图。
- 其他数据库对象。

支持展开、折叠、搜索和刷新。

允许调整左侧区域宽度。

## 3.5 中央工作区域

主要展示：

- 数据库连接信息。
- 表数据。
- 表结构。
- SQL 查询编辑器。
- SQL 查询结果。

采用多标签页模式。

## 3.6 底部区域

显示：

- SQL 执行消息。
- 查询结果。
- 执行耗时。
- 影响行数。
- 错误信息。

支持调整高度和折叠。

# 4. 数据源连接管理

## 4.1 连接列表

支持：

- 新建连接。
- 编辑连接。
- 删除连接。
- 复制连接。
- 测试连接。
- 建立连接。
- 断开连接。
- 重命名。
- 分组。
- 搜索连接。
- 刷新连接。
- 展开和折叠。

连接列表应保存用户配置。

## 4.2 新建连接

点击新建连接后打开连接配置窗口。

### 基础配置

| 字段       | 类型     | 必填 | 说明           |
| ---------- | -------- | ---- | -------------- |
| 连接名称   | String   | 是   | 自定义名称     |
| 数据库类型 | Enum     | 是   | V1 仅 MySQL    |
| 主机地址   | String   | 是   | 数据库主机     |
| 端口       | Integer  | 是   | 默认 3306      |
| 用户名     | String   | 是   | 数据库用户     |
| 密码       | Password | 否   | 数据库密码     |
| 默认数据库 | String   | 否   | 默认数据库     |
| 连接超时   | Integer  | 是   | 建议默认 10 秒 |

### 高级配置

预留：

- 字符集。
- SSL。
- SSH 隧道。
- 连接参数。

SSH 隧道暂不要求实现。

## 4.3 测试连接

用户填写配置后可以测试连接。

流程：

1. 前端校验参数。
2. 调用 Rust 后端。
3. 后端建立临时连接。
4. 返回测试结果。
5. 展示连接成功或失败信息。
6. 释放临时连接。

成功时展示数据库版本等基本信息。

失败时展示可读的错误原因。

## 4.4 建立连接

连接成功后：

1. 更新连接状态。
2. 获取数据库信息。
3. 加载数据库列表。
4. 展示资源树。
5. 允许用户操作数据库。

连接状态：

- 未连接。
- 连接中。
- 已连接。
- 正在断开。
- 连接异常。

## 4.5 多连接管理

支持同时保存多个 MySQL 连接。

不同连接必须具有独立的：

- 连接状态。
- 数据库会话。
- 当前数据库。
- 查询任务。
- 工作标签。
- 查询历史。

一个连接断开不能影响其他连接。

## 4.6 连接配置持久化

连接配置保存在本地。

密码使用操作系统凭据管理机制保护。

SQLite 不得直接保存明文密码。

# 5. 数据库资源管理器

## 5.1 数据库列表

连接成功后获取数据库列表。

支持：

- 展开。
- 折叠。
- 刷新。
- 搜索。
- 设置当前数据库。

## 5.2 数据库对象结构

```
database_name
├── Tables
│   ├── users
│   ├── orders
│   └── products
├── Views
│   ├── user_view
│   └── order_view
├── Functions
└── Procedures
```

V1 重点实现 Tables 和 Views。

## 5.3 表列表

展示：

- 表名称。
- 表类型。
- 表注释。

支持：

- 搜索表名。
- 刷新表列表。
- 双击打开数据。
- 右键菜单。

## 5.4 表右键菜单

提供：

- 打开表。
- 查看数据。
- 查看结构。
- 查看索引。
- 新建查询。
- 复制表名。
- 复制建表 SQL。
- 刷新。

## 5.5 资源加载

采用按需加载机制。

不能在连接成功时一次性加载所有数据库的所有表结构。

用户展开对应资源时再获取数据。

# 6. SQL 编辑器

## 6.1 基本功能

使用专业代码编辑器组件，建议采用 Monaco Editor。

支持：

- SQL 语法高亮。
- 关键字识别。
- 行号。
- 当前行高亮。
- 括号匹配。
- 自动缩进。
- 代码折叠。
- 查找替换。
- 撤销重做。
- 复制粘贴。
- 多行编辑。

## 6.2 多标签页

每个 SQL 编辑器标签拥有独立状态：

- 所属连接。
- 当前数据库。
- SQL 内容。
- 编辑状态。
- 文件路径。
- 查询结果。

未保存的内容需要显示修改标识。

关闭未保存标签时提示：

- 保存。
- 放弃修改。
- 取消关闭。

## 6.3 SQL 文件

支持：

- 新建 SQL 文件。
- 打开本地 SQL 文件。
- 保存。
- 另存为。
- 修改后保存。
- 关闭提示。

SQL 文件与数据库连接配置分开管理。

## 6.4 数据库选择

编辑器必须明确显示：

- 当前连接。
- 当前数据库。

用户可以切换执行上下文。

已经开始执行的查询必须保持原来的连接和数据库上下文。

## 6.5 SQL 执行方式

支持：

1. 执行当前 SQL。
2. 执行选中 SQL。
3. 执行全部 SQL。

多语句执行应按照顺序处理，并展示每条语句的执行状态。

## 6.6 SQL 执行状态

状态包括：

- 等待执行。
- 执行中。
- 执行成功。
- 执行失败。
- 已取消。
- 超时。

执行期间显示执行时间和取消操作。

## 6.7 SQL 结果类型

| SQL 类型 | 处理方式   |
| -------- | ---------- |
| SELECT   | 表格结果集 |
| SHOW     | 表格结果集 |
| DESCRIBE | 表格结果集 |
| EXPLAIN  | 表格结果集 |
| INSERT   | 影响行数   |
| UPDATE   | 影响行数   |
| DELETE   | 影响行数   |
| CREATE   | 成功消息   |
| ALTER    | 成功消息   |
| DROP     | 成功消息   |

不能假设所有 SQL 都会返回数据表格。

## 6.8 SQL 执行限制

- 默认查询超时建议 60 秒。
- 支持取消查询。
- 限制单次返回数据量。
- 长时间查询不能阻塞 UI。
- 查询失败必须展示错误。
- 不能将取消请求误报为底层 SQL 已成功终止。

## 6.9 SQL 安全

- SQL 必须由用户明确触发。
- 不得自动执行用户编写的 SQL。
- 不得在连接时执行历史 SQL。
- 危险操作应提供必要提醒。
- 不得记录数据库密码。

# 7. 数据浏览器

数据浏览器是 V1 的核心功能之一。

## 7.1 打开表数据

用户可以通过以下方式打开表数据：

- 双击左侧表名称。
- 右键选择查看数据。
- 通过数据库对象菜单打开。

打开后在中央工作区创建数据浏览标签页。

## 7.2 数据展示

采用专业数据库客户端的表格布局。

展示：

- 字段名称。
- 字段数据。
- 行号。
- 主键标识。
- 当前记录状态。

支持：

- 单元格选择。
- 行选择。
- 列选择。
- 多行选择。
- 复制单元格。
- 复制行。
- 复制多行。
- 列宽调整。
- 列排序。
- 列显示和隐藏。

对于 NULL、空字符串和特殊类型，应提供清晰的视觉区分。

## 7.3 数据分页

不允许一次性加载整张表。

支持：

- 上一页。
- 下一页。
- 跳转页码。
- 每页记录数调整。
- 当前记录范围显示。

建议默认每页 100 条。

提供 50、100、200、500 等分页选项。

分页策略应考虑表是否存在稳定排序字段。

没有明确唯一排序条件时，必须注意分页结果的稳定性，不能简单依赖无序查询。

## 7.4 数据筛选

支持基础条件筛选。

包括：

- 字段选择。
- 条件选择。
- 输入值。
- 添加条件。
- 删除条件。
- 执行筛选。
- 清除筛选。

常见条件：

- 等于。
- 不等于。
- 大于。
- 小于。
- 大于等于。
- 小于等于。
- LIKE。
- IN。
- IS NULL。
- IS NOT NULL。

条件查询必须使用安全的参数化构造方式。

## 7.5 数据排序

支持点击列标题进行排序。

包括：

- 升序。
- 降序。
- 取消排序。

排序字段必须来自真实表字段，不允许直接拼接未经校验的用户输入。

## 7.6 数据新增

支持新增记录。

提供适合字段类型的编辑方式。

包括：

- 文本。
- 数字。
- 日期。
- 时间。
- 布尔值。
- NULL。
- 其他特殊类型。

新增时：

- 必填字段应有提示。
- 默认值应合理处理。
- 自增字段可以自动生成。
- 保存前进行必要校验。
- 保存成功后刷新或更新当前结果。

## 7.7 数据编辑

支持直接编辑单元格。

编辑状态应具有明显区分。

用户修改后可以：

- 保存修改。
- 取消修改。

对于同一条记录的多个字段修改，建议合并成一次 UPDATE 操作。

更新操作必须具有可靠的记录定位条件。

不能仅依赖普通字段值定位记录。

优先使用主键或唯一键。

对于没有主键或唯一键的表，应提供谨慎的编辑策略，避免错误更新多条记录。

## 7.8 数据删除

支持删除选中记录。

删除前必须二次确认。

删除成功后刷新结果集。

对于批量删除，应明确显示影响范围。

## 7.9 数据导出

第一阶段建议支持：

- CSV。
- JSON。

导出范围：

- 当前查询结果。
- 当前页数据。
- 用户选中的记录。

导出前允许用户选择保存路径。

大数据导出需要采用流式或分批处理，避免一次性占用大量内存。

## 7.10 数据复制

支持：

- 复制单元格。
- 复制当前行。
- 复制选中行。
- 复制为 JSON。
- 复制为 SQL INSERT 语句。

## 8.2 索引查看

## 8.3 建表 SQL

## 8.4 表结构编辑

# 12. 数据安全与操作保护

## 12.1 密码保护

数据库密码必须使用操作系统凭据存储机制保护。

不能明文写入普通配置文件。

## 12.2 危险操作保护

以下操作需要明确确认：

- DELETE。
- DROP。
- TRUNCATE。
- 批量 UPDATE。
- 批量 DELETE。
- 表结构修改。

对于生产环境连接，可以考虑增加更明显的环境标识和危险操作提醒。

## 12.3 数据隔离

不同连接之间的数据必须隔离。

不能错误地将一个连接的查询结果展示到另一个连接的工作区。

## 12.4 日志安全

日志不能包含：

- 数据库密码。
- 明文认证凭据。
- 不必要的敏感参数。
- 完整的敏感业务数据。

# 13. 非功能性需求

## 13.1 性能

- 应用启动尽量快速。
- UI 操作保持流畅。
- 数据库操作不得阻塞界面。
- 大量数据采用分页或分批加载。
- 不必要的数据库对象不得提前加载。
- 多连接之间相互隔离。

## 13.2 稳定性

- 连接断开能够识别。
- 查询失败不影响整个应用。
- 后台任务能够正常取消。
- 单个连接异常不能导致其他连接异常。
- 应用退出时合理释放资源。

## 13.3 易用性

- 常用功能容易找到。
- 操作路径尽量简短。
- 危险操作具有明确提示。
- 错误信息容易理解。
- 新用户能够快速掌握基本操作。

## 13.4 跨平台

确保主要功能在 macOS、Windows 和 Linux 上具有一致的操作体验。

系统原生差异应由应用适配层处理。

# 17. 产品设计最终要求

DataDock 不应当只是一个能够连接数据库、执行 SQL 的简单工具。

它应当具备完整数据库客户端的使用体验。

产品设计必须始终坚持：

1. 以 Navicat 作为主要产品体验参考。
2. 保持数据库客户端的专业操作习惯。
3. 采用现代化、精致、优雅的视觉设计。
4. 合理使用 Glassmorphism 玻璃拟态。
5. 支持深色和浅色两套完整主题。
6. 重视数据表格的清晰度和操作效率。
7. 不使用传统后台管理系统式布局。
8. 不使用 VS Code 式 IDE 作为整体界面方向。
9. 不以组件库默认样式代替产品设计。
10. 不为了视觉效果牺牲实际功能体验。

**DataDock 的目标是：既拥有成熟数据库客户端的专业体验，又具备现代桌面应用的精致视觉品质。**

让用户打开应用的第一眼，就能感受到它的设计品质；长期使用时，又能感受到它的高效和顺手。
